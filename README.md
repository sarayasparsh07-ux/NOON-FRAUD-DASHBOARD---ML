## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m ipykernel install --user --name python3
python notebooks/build_and_run.py          # Phase 1 full run, ≈26 min on 2 CPU cores (corrected from an earlier ≈40–50 min estimate)
# FRAUD_DEV=1 python notebooks/build_and_run.py   # 3-minute smoke test (fewer epochs/seeds; not the reported results)
python -m src.build_register               # re-render reports/assumptions_register.md from the generator parameters
python notebooks/run_phase2.py             # Phase 2: ≈15 min on 2 CPU cores; appends to the notebook
# Phase 3 (once): Noon model cross-version check in an isolated environment — the project environment is not touched
python -m venv venv_sk180 && venv_sk180/bin/pip install scikit-learn==1.8.0 pandas joblib
venv_sk180/bin/python -I -B notebooks/phase3_noon_crossversion.py "$PWD" "$PWD/outputs/phase3/audit/noon_predictions_sklearn_1.8.0.csv"
python notebooks/run_phase3.py             # Phase 3: ≈1.5 min; appends to the notebook
```

Run the steps in this order: `build_and_run.py` rebuilds the notebook from the Phase 1 source only, so `run_phase2.py` and then `run_phase3.py` must follow it.

**Phase 2** reads the professor files from `professor_supplied/` and checks their hashes first. It verifies that the Phase 1 notebook cells are unchanged before and after appending. The referee file is opened once for integrity counts only and is never used for development. Re-running Phase 1 (`build_and_run.py`) rebuilds the notebook without the Phase 2 cells, so run `run_phase2.py` afterwards.

All randomness is seeded (master seed 42; repeats 42, 7, 101, 2024, 31337). Two complete runs of the notebook produced identical results: the seed data (bit-for-bit, also checked by the audit), the CTGAN loss curve and generated rows, every classifier metric, selection and threshold. One exception in Phase 1: SDMetrics' `LogisticDetection` diagnostic uses an unseeded internal split and varied by up to ±0.02 between runs (no decision depends on it); Phase 2 does not use SDMetrics. The Phase 2 lie detector uses 10 seeded repeats. Different hardware or library versions may produce small numerical differences in the GAN and therefore in the augmented arms.

## Phase 4 — Run the fraud-check app

```bash
# once, from the project root (Python 3.13)
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt            # full project; or, for the app alone: pip install -r requirements-app.txt

# start the app (opens http://localhost:8501)
streamlit run app.py
```

* Enter the ten transaction details and press **Check transaction**. The page shows **FRAUD — FLAGGED FOR MANUAL REVIEW** or **LEGIT — NOT FLAGGED BY THE MODEL**, the Model Fraud Score and the frozen threshold (0.297).
* The verdict is exactly `models/fraud_model.joblib`'s own `predict()`, the Phase 1 selected classifier (arm A, baseline). The app passes the raw columns; the saved pipeline does its own encoding, calibration and thresholding.
* Stop the app with **Ctrl + C** in the terminal; run the same command to restart it.
* The app works from any folder (`streamlit run /path/to/Noon_Fraud_Detection/app.py`). Start it from the project root so `.streamlit/config.toml` applies: localhost only, no usage telemetry.
* It needs no internet, database or API, and it does not store what you type.
* It is an **academic prototype**. On Noon's real referee data this model caught 44 of 65 frauds but flagged 1,036 legitimate orders (precision 4.1%), so a FRAUD verdict is a prompt for human review, never grounds for automatic action.

## Using the saved model

```python
import joblib, pandas as pd, sys
sys.path.insert(0, ".")                      # the model object is defined in src/modeling.py
model = joblib.load("models/fraud_model.joblib")
tx = pd.DataFrame([{"order_amount": 240.0, "account_age_days": 2, "hour_of_day": 3, "num_orders_last_7d": 4,
                    "payment_method": "card", "delivery_distance_km": 6.5, "discount_applied": 0,
                    "prev_refunds": 0, "device_change": 1, "location_mismatch": 1}])
p = model.predict_proba(tx)[0]               # calibrated to the SYNTHETIC world only
print(f"fraud score {p:.3f} → {'FRAUD' if p >= model.threshold else 'LEGIT'} (threshold {model.threshold:.3f})")
```

## Important limitations

* Phase 1 and 2 results are measured on synthetic data. Phase 3 is the real test: on the referee set my selected classifier catches 44 of 65 real frauds with 1,036 false positives, while Noon Model B catches 53 with 71 false positives (`reports/phase3_report.md`).
* In Phase 1, the optional evaluation helper and the `app.py` shell had not been supplied, so Phase 1 metrics were computed with scikit-learn. Both now exist in `professor_supplied/`. Phase 2 uses the helper's `compare_distributions` and `lie_detector` and reports where their assumptions do not hold: duplicate leakage, and a 0.50 reference that ignores unequal file sizes. In Phase 3, `score_on_referee()` is used for Noon's model (my custom models are scored through their own `predict`, which applies their stored thresholds). In Phase 4, `app.py` replaces the professor's shell logic because my model takes raw columns and has its own threshold; `professor_supplied/app(2).py` is kept unmodified (`reports/phase4_implementation_notes.md`).
